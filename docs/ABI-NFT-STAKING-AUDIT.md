# NFT and staking ABI audit - 29.10.2026

This is a static ABI/source audit, not a claim of network execution for every method. All 64 NFT/Staking OperationCatalog rows were inspected through their actual offline fixture selector. There are 57 relevant SDK Function DTOs and 172 function entries across the five older go-smart-node ABI files. Matching the union of those ABIs alone does not establish that a function targets the right deployed contract.

## Evidence and limits

- Current official JS SDK checkout: `c7a72278551c517d3c0a37e170f844e8176e385f`, `src/decimalevm/call.ts`. Its checked-in `src/decimalevm/abi/` has only Checks.json and Multicall.json. NFT and delegation contracts obtain ABI dynamically in `src/decimalevm/contract.ts` from `v1/contracts/compact/{address}`. No complete current NFT/staking ABI JSON is claimed here.
- Older go-smart-node snapshot: `9e6c6d718d662083c4a524376a66d2c50bd4bc77`, contracts/nft721/DecimalERC721.json, nft1155/DecimalERC1155.json, nftCenter/DecimalNFTCenter.json, delegation/DecimalDelegation.json and delegationNft/DecimalDelegationNFT.json. These are protocol evidence, not current runtime certification.
- Vendored SDK snapshot stays unchanged. `artifacts/abi-nft-staking-audit.json` contains each exact SDK signature, selector, matching node ABI source and catalog operation. Audit helper resides in ignored artifacts/abi-nft-staking-audit-tool.

## Concrete differences and coverage

1. Native NFT mint: SDK `mintByETH(address,string)` and `mintByETH(address,uint256,uint256,string)` differ from current JS `mintByDEL` with the same argument types. Actual fresh QA ERC721 mintByDEL succeeded on testnet. `CurrentNftDrafts` contains both the original testnet-only synchronous adapter and a new asynchronous compatibility selector for mainnet/testnet. The asynchronous path preserves a working ETH draft; it tries the DEL replacement only after ContractRejected and returns it only after a successful gas estimate, preserving target, payload, sender and native value. Callers must use the asynchronous path in the app.
2. Native reserve top-up: SDK `addReserveByETH(uint256)` vs JS `addReserveByDEL(uint256)`. The same asynchronous compatibility selector covers it on both supported chains, preserving a working legacy deployment. Explicit SDK BuildAddDelReserveDraft already encodes the current name but requires its unverified-ABI flag.
3. Creation: older go-node/current SDK modern builders encode `createERC721((address,string,string,string,bool))` / ERC1155. Current JS and testnet receipt proof use `createDRC721((address,string,string,string,bool,bool))` / DRC1155. These tuples have different semantics (refundable vs allowMint/burnable); they must not be silently converted. Explicit SDK legacy builders preserve the six-field metadata. Modern builders are now hidden in testnet generic tools. The mainnet read-only probe below also rejects them, so the same unsupported-profile guard is required there. No automatic conversion of refundable into allowMint/burnable is justified.
4. Separate NFT delegation: `delegateDRC721`, `delegateDRC1155`, `delegateHoldDRC721`, `delegateHoldDRC1155`, `withdraw(address,address,uint256,uint256)`, `withdrawHold(address,address,uint256,uint256,uint256)`, `transfer(address,address,uint256,uint256,address)` and `transferHold(address,address,uint256,uint256,uint256,address)` match the legacy separate delegationNft ABI. Current JS retains those wrappers. They are not valid substitutes for current combined testnet `delegateNFT` / `delegateNFT1155` / `withdrawNFT` / `withdrawNFT1155` / transferNFT variants.
5. Current combined NFT withdrawal takes the whole position and no amount. `StakingNftDrafts` correctly distinguishes 721/1155 and Hold variants. Testnet generic legacy NFT drafts are blocked; the dedicated workspace uses the pinned implementation profile. Mainnet uses its existing separate legacy path, whose deployment compatibility is not inferred from testnet.
6. ERC20/DEL DelegationDrafts selectors including `hold`, `resetHold`, `resetHolds`, `withdrawWithReset`, `transferHold`, `transferWithReset`, `holdWithReset` all exactly match the pinned go-node ABI parameter types. This is static evidence; not all hold/reset/validator scenarios were executed.
7. NFT-specific legacy hold/reset helpers in current JS include `hold(address,address,uint256,uint256,uint256,uint256)`, `resetHold(address,address,address,uint256,uint256)`, `resetHolds(address,address,address,uint256,uint256[])`, `withdrawWithReset(address,address,uint256,uint256,uint256[])`, `transferWithReset(address,address,uint256,uint256,address,uint256[])`, `holdWithReset(address,address,uint256,uint256,uint256,uint256[])`. These wrappers call `this.delegationNft` (the separate legacy module), not the new combined `this.delegation` contract. They are not SDK OperationCatalog entries. Some are absent from the pinned older NFT delegation ABI and have no verified current testnet combined equivalent. They are historical/advanced legacy API scope, not established missing consumer operations of the current combined contract. A token-staking reset must never be substituted for an NFT reset by dropping tokenId.
8. Current JS additionally exposes NFT mintByPermit and addReserveByPermit, reservless collection creation and several owner metadata operations which are not represented by the 118-method SDK catalog. The catalog count therefore is not an exhaustive Decimal contract-function count. Unsupported or unverified variants must stay explicit rather than be reported as fully ready.

## Scope boundary

The consumer wallet scope covers ordinary assets, NFT author operations and a user's validator. Contract initialization/upgrades, global governance and deprecated legacy-only helpers are separate advanced protocol administration scope. They are listed for honesty rather than counted as unfinished ordinary wallet transaction types. ABI matches, read-only behavioral probes and confirmed state-changing testnet lifecycles remain separate evidence categories.

## Mainnet NFT staking routes are deployment-specific

A bounded read-only registry probe at mainnet block34335335 resolved separate NFT delegation to `0xE45ADFCC739a0d10CE9462B58866c9A1a06035E2` (ERC1967 implementation `0xaffe98bbd4c74ccc95d7d99a684bd83fecaece6c`,23430runtime bytes, SHA256 `0bcbefa0ec42d8c720dd4452c7bf95aa414f14c2b222ab1d5889db7955d54639`). Its legacy `getStake(address,address,address,uint256)` returned a well-formed empty seven-word tuple. `delegateDRC721` reached a nonempty typed revert `0xd93c0665`, which matches `EnforcedPause()`; it is not `InvalidValidator()` (that signature is `0x682a6e7c`). The source of a nested revert cannot be established solely from this selector.

The mainnet registry's token/DEL delegation route is `0xA16c34Ed1c0601c0E749e17ebeF19752A15FaA01`, implementation `0xa4567e1a2182b630fb57441ae788dce98721d358`,23325runtime bytes, SHA256 `96809735dbb00df5a6ce0d8b407818990d9e96570b9e58f02311a38ac50a56a0`. Its tested `getNFTStake` and `delegateNFT` calls reverted with empty data. It does not match the24316byte implementation pinned for the current testnet combined NFT profile. Therefore the mainnet route must not be redirected to that testnet combined ABI merely because new JS helpers exist.

Mainnet legacy getStake dispatch was accepted; the tested delegate preflight returned EnforcedPause and is not a successful mainnet delegation proof. No deprecated-contract message appeared in these probes. No production validator validity or permission is inferred from the nonzero validator argument. The sample NFT's current owner is the legacy NFT-delegation contract itself, consistent with an existing staked position; no transfer or state change was attempted.

A follow-up queried only `paused()` on those two registry routes and the selected public NFT collection. The legacy NFT-delegation contract returned true (ABI bool word1); token/DEL delegation returned false (word0). The NFT collection getter reverted with empty data, so collection pause state remains unknown. Thus a pause on the outer legacy NFT-delegation contract is directly observed, consistent with its delegate preflight returning EnforcedPause. This is an external on-chain condition, not permission to unpause and not an absent ABI. Exact results: `artifacts/mainnet-nft-audit/mainnet-nft-pause-origin.json`. No unpause action, signing or broadcast was attempted. The behavior of other write methods while paused is not assumed without individual simulation.

Regression tests preserve mainnet legacy `delegateDRC721` and its separate target, keep testnet dedicated `delegateNFT` on the pinned combined proxy, and prevent the testnet-only builder from silently accepting mainnet.
