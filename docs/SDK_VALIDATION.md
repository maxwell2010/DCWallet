2026-10-29 additions also include reserve-backed token reads and exact-input/output economy drafts, NFT metadata and selected current-ABI mint/reserve drafts, validator record/reward/penalty reads, Checks owner/implementation reads, bridge minimum service fee read, a reusable C# transaction signer, locally computed signed-transaction hash, classified transaction errors, Safe read queries and `approveHash` draft, NFT staking drafts/reads, NFT receipt decoding, Checks redemption hash/receipt helpers, bridge fee quote helpers and ERC20 batch transfer drafts. The direct ERC20 batch fallback passes offline tests; the pinned CandySafeMultisend permit path has one successful live testnet transaction. Bridge settlement, Safe deployment/threshold execution and broad NFT/ERC20 staking flows remain unverified or incomplete.

Safe execution preflight checks chain ID, a block-pinned nonce and signer membership. It deliberately does not equate signature count with Decimal Safe's weighted quorum; a live Safe and fee estimation are needed to establish executable signatures.

The public testnet coin API identified reserve-backed token `0x37748f3e857a71e4334125a935052ce1e603b7b5`; C# reserve/CRR reads, buy/sell quotes and a small-buy gas estimate passed. No reserve-backed write was sent. The current-ABI `getNftType()` call reverted on the existing QA collection, so NFT writes must be matched to that deployment's ABI before broadcasting. Contract Center's testnet `delegation-nft` address `0x07e2ad4dfc91412de09e33e4650254948b21a20c` reports that it is deprecated; the NFT stake selectors also revert on the suggested `DecimalDelegation` address. NFT staking reads and writes therefore remain unverified for this deployment.

The package is an alpha implementation, not a feature-complete replacement for the Python SDK. Draft builders verify local calldata structure, but cannot prove that a deployed contract accepts the call. Checks and bridge-v2 currently follow local Python ABI definitions, not a confirmed deployment in the current official node source. Do not infer a payable fee from a failed estimate or assume that an approval can be safely merged into an arbitrary Multicall transaction. The default Decimal testnet RPC and a locally configured RPC both timed out on `eth_chainId`; the fallback used for these tests was the public `https://202020.rpc.thirdweb.com` endpoint. The test wallet held 877.201578893512203934 DEL before the first self-transfer and 875.800544269048132764 DEL after reservless burn; no faucet request was needed. The receipt fee fallback reads the legacy transaction's gas price when the RPC omits `effectiveGasPrice`. The testnet WDEL address must be resolved from Contract Center (`wdel`), not copied from mainnet defaults. A `mint(address,uint256)` call was confirmed only for the newly deployed reservless token, not for reservable DecimalToken contracts.

Reservless token updates `updateTokenIdentity`, `updateMaxTotalSupply`, `updateMinTotalSupply` and `updateDetails` reverted during testnet fee estimation on the deployed `sdkcsqa` token. These are not advertised as working reservless operations. Even a checked mint/burn draft can become stale if the contract state changes; call `EstimateFeeAsync` immediately before signing.

To repeat the offline suite:

```powershell
dotnet test csharp/tests/Decimal.Web3.Tests/Decimal.Web3.Tests.csproj -v:q
dotnet pack csharp/src/Decimal.Web3/Decimal.Web3.csproj -c Release -v:q
```

No mnemonic, private key or private endpoint is required for these checks. Network tests are opt-in and read-only unless the caller explicitly signs and broadcasts a transaction.
