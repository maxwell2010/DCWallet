# DC WALLET 0.2.0-alpha.3 - функциональная проверка

Дата: 29.10.2026. Мост исключен из текущего объема по указанию пользователя. Публичной публикации на GitHub не выполнялось.

## Изменения

- Приватный ключ импортируется в типизированный зашифрованный vault v2. BIP39 vault v1 совместим, смена пароля и восстановление сохраняют тип. Независимые профили используют отдельные файлы; прежний wallet.vault сохраняется.
- WalletSigningSession подписывает транзакции, Safe digest и permit. Приватный ключ дает один адрес, seed-профиль - десять. Смена профиля блокирует сессию.
- Safe поддерживает Call/DelegateCall, динамические подписи владельцев-контрактов, EOA и approved_hash. Перед подписанием и исполнением проверяются параметры, nonce, владелец, hash и симуляция самого Safe. DelegateCall требует отдельного выбора и подтверждения.
- Чеки: отдельный зашифрованный bearer-файл, DEL/ERC20/permit, точный approve, свежий creator-scoped nonce, проверка предсказанного hash по receipt, погашение и защита от replay. Файл сохраняется до создания. Mainnet direct-runtime профиль прошел readonly VerifyAsync и create eth_call, без mainnet подписи/отправки.
- NFT721/1155: актуальные combined delegate/withdraw/transfer/Hold, ручной расширенный NFT721 permit. В testnet native-reserve методы адаптированы с mintByETH/addReserveByETH к mintByDEL/addReserveByDEL. Для testnet создание использует совместимый legacy-профиль.
- История распознает намерения вызовов по ABI/DTO. Внутренний отказ Safe отделен от внешнего статуса receipt, отображается явно и экспортируется отдельной колонкой CSV. Проверки каноничности и владения сохранены.
- Создание токенов: wallet receipt reader распознает актуальное событие TokenDeployed с metadata tuple и старое address-only событие. Созданный адрес показывается после квитанции.

## Автоматические проверки

322 Core + 35 Avalonia Headless = 357 успешных автоматических тестов. 23 отдельных сетевых/fork opt-in тестов пропущены в обычном прогоне и запускаются явно. Сборка без предупреждений. После обновления генератора матрицы его отдельный прогон прошел с указанием Console source.

Визуально проверены светлая, темная и Криптопанк темы для профилей, импорта ключа, чеков и расширенного Safe. Некорректный ключ не выводится в ошибке и не создает vault.

Независимый финальный аудит подтвердил все 29 receipts, отправителей, nonce, destination/value, канонические блоки, фактические комиссии и init/runtime QA deployment. Все 29 журналов confirmed, pending0. Safe hash пересчитан по calldata и проверен по внутренним событиям. Отдельный state audit подтвердил конечные балансы, владельца NFT, статусы заявок, nonce Safe и разрешения.

Публичные доказательства в игнорируемой локальной папке artifacts/completion-testnet: completion-receipt-audit.json, completion-final-state.json, отдельные run-*/report.json. Seed, приватные ключи кошелька и raw signed transactions в отчеты не записываются. Временные bearer backup удаляются после успешного погашения и replay-проверки.

Потерянный RPC-ответ на CREATE восстановлен по исходному локальному hash; развертывание не повторялось. После ошибок readonly-запросов завершение выводов продолжалось по сохраненным координатам; повторных create/mint/complete/sell не выполнялось.

Стандартный предел комиссии тестов 0.5 tDEL; отдельные явно проверенные исключения: создание NFT721 до 0.6 и его delegate до 0.7 tDEL. Общий лимит каждого изолированного запуска 5 tDEL. Значения исключений и фактические комиссии записаны до отправки.

## Локальный fork

5 отдельных Ganache-проверок прошли: совпадение исходного code/storage/balance с testnet, истечение чека, owner-роли, создание резервного токена и DEL Hold/reset после двух лет time travel. Это локальный EVM-прогон, не публичные транзакции.

Ganache требует metadata earliest block, которую Decimal RPC не возвращает. Использован только metadata fallback на закрепленный fork block; code/storage/balances не подменялись. Ethereum header Ganache имеет другой hash, чем канонический Decimal header. Ограничение отражено в [LOCAL-FORK-VALIDATION.md](LOCAL-FORK-VALIDATION.md). Снимки откатывались после тестов; запущенный агентом сервер остановлен.

## Платформы и границы выводов

Все 6 RID собраны self-contained; Windows x64 готовый файл проходит self-test. Нативные Linux/macOS/ARM64 запуски и упаковка требуют соответствующих CI runners. WSL-дистрибутивов и работающего Docker Linux Engine в этой среде нет. Cross-build не является нативной проверкой.

Полный fixture-каталог 118 SDK builders не означает 118 уникальных типов транзакций или подтверждение всех ABI/ролей в публичной сети. Статус каждого семейства и ограничения: [CAPABILITIES.md](CAPABILITIES.md), [TRANSACTION-MATRIX.md](TRANSACTION-MATRIX.md). Все возможные NFT/hold/permit комбинации и административные роли валидаторов не сертифицированы данным публичным прогоном. Для произвольных владельцев-контрактов Safe окончательным условием остается совместимость с signature hook развернутого Safe и успешная симуляция.

Обнаружен внешний блокер mainnet NFT-стейкинга: текущий registry delegation-nft 0xE45ADFCC739a0d10CE9462B58866c9A1a06035E2 вернул paused=true, а проба делегирования - EnforcedPause(). Отдельный token/DEL delegation вернул paused=false. Кошелек проверяет паузу до нового NFT approval/делегирования, не пытается unpause и не блокирует остальные методы без их индивидуальной симуляции. Mainnet сохраняет свой legacy маршрут; testnet combined ABI туда не переносится. Доказательства: [ABI-NFT-STAKING-AUDIT.md](ABI-NFT-STAKING-AUDIT.md).

Мост остается за пределами текущего этапа. Нативный CI, финальный просмотр условий распространения и решение о публичной публикации выполняются отдельно. Статус сборки остается alpha.
